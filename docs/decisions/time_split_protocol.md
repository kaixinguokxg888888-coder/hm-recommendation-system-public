# 时间切分与泄漏防护协议

决策编号：`SPLIT-001`

状态：`FROZEN`

## 1. 配置规则

设完整数据最大日期为 `D_max`，当前为 2020-09-22。所有区间按自然日闭区间定义。

| 方案 | Train | Validation | Test | 用途 |
| --- | --- | --- | --- | --- |
| 14 天主方案 | `t_dat <= D_max-28d`，当前截至 2020-08-25 | 2020-08-26 至 2020-09-08 | 2020-09-09 至 2020-09-22 | 主模型选择与最终一次测试 |
| 7 天快速方案 | `t_dat <= D_max-14d`，当前截至 2020-09-08 | 2020-09-09 至 2020-09-15 | 2020-09-16 至 2020-09-22 | 快速开发方向检查 |
| 28 天稳健方案 | `t_dat <= D_max-56d`，当前截至 2020-07-28 | 2020-07-29 至 2020-08-25 | 2020-08-26 至 2020-09-22 | 冷启动与长期稳健性 |

Stage 1B 已验证各方案最后一个 test 窗口的规模；前置 validation 窗口的完整指标需在 Stage 2 按本规则计算。

## 2. 主窗口理由

最后 14 天窗口：

- 495,552 条原始测试记录；
- 117,366 个可评用户；
- test 用户训练期可见率 91.45%；
- 单正样本用户率 25.76%；
- warm user-item 行覆盖上限 83.95%。

相比 7 天，它提供更多可评用户和更低单正样本比例；相比 28 天，它的冷商品率和候选覆盖损失更可控。因此冻结为主方案，不代表它在所有业务目标上最优。

## 3. 两阶段模型选择

1. 在 train 上构建召回、特征统计和排序模型；
2. 在 validation 上选择口径、超参数、配额和重排阈值；
3. 冻结配置；
4. 允许使用 train+validation 重新拟合最终模型；
5. test 只执行一次最终比较，不用于调参或选择实验。

## 4. 截止时间

- validation 请求时点：2020-08-26 00:00；所有统计和召回训练最多使用 2020-08-25。
- test 请求时点：2020-09-09 00:00；最终重训最多使用 2020-09-08。
- 标签分别来自请求时点开始的连续 14 日。
- 任一记录的特征版本必须携带 `as_of_date`。

## 5. 泄漏防护

- 禁止随机切分；
- 禁止用标签窗口计算热度、共现、用户历史、归一化参数、截断分位数或负采样分布；
- 商品静态属性也必须采用请求时点可知版本；当前数据没有属性生效时间，需记录这一局限；
- 候选召回必须按历史快照重放，不能从完整数据生成后再过滤；
- 用户分群只依据 cutoff 前的 B 口径历史；
- test 指标不得进入参数、模型或方案选择。

## 6. Rolling backtest

优先级为 P1。在 V1 P0 链路可信后，增加至少三个向前滚动的 14 天 validation 切点，报告用户分块 paired bootstrap 95% 区间和跨窗口方向一致性。资源不足时优先保留主 14 天切分与 7/28 天稳健检查。
