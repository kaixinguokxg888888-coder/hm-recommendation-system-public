状态：`FROZEN_FOR_V1_ROUTE`

本矩阵是路线决策，不是效果声明。证据来自 `artifacts/stage_1b/model_evidence_matrix.csv` 及 Stage 1A/1B 聚合结果。

## 2. 候选融合

| 方案 | V1 决策 | 理由 |
| --- | --- | --- |
| 固定配额 union | 采用 | 可解释、可复现，可直接测独立贡献和 union 增益 |
| Round-robin | P1 对照 | 可改善来源平衡，但可能牺牲强来源头部候选 |
| 简单加权 | P1 | 需要 validation 上完成跨来源分数标定 |
| 训练式融合 | 暂缓 | 当前没有稳定候选日志和无偏监督信号 |

## 3. 粗排

V1 不设置独立粗排。候选硬上限 1,000，可直接由 LightGBM 精排。只有候选超过 3,000 或特征/评分 P95 预算不达标时才触发粗排设计。

## 4. 精排

| 方案 | 决策 | 原因与边界 |
| --- | --- | --- |
| 来源规则分数 | P0 baseline | 验证候选链路和数据泄漏 |
| LightGBM ranking | V1 强基线 | 适配表格聚合特征、可解释、训练与服务成本可控 |
| LR/普通 GBDT | P0/P1 对照 | 检查复杂度是否真正带来收益 |
| DeepFM | P1 challenger | 只能在可重放候选样本上对照；不输出 CTR |
| Wide&Deep | P2 | 与 DeepFM 信息增量可能有限，优先级更低 |
| 双塔分数特征 | P2 | 依赖双塔先证明召回互补 |
| DIN/序列特征 | P2 active-only | 只适用于历史足够长的子群 |

排序负例是“候选中标签窗口未观察到购买”，不是用户真实不喜欢。目标是相对排序分数，不是校准 CTR/CVR。

## 5. 重排

采用确定性规则作为 V1：article 去重、product/garment group 上限、已购控制、热门度监控、冷商品有限探索。多目标学习式重排暂缓，先确保 MAP/NDCG 不因多样性显著下降。

## 6. 通过门禁

任何 challenger 进入 V1 主线，必须同时满足：

1. 14 天 validation 主指标优于当前强基线；
2. 7 天或 rolling 窗口方向一致；
3. cold/short/warm/active 关键分群无不可接受退化；
4. 独立贡献或 union 增益可量化；
5. 资源成本满足 Stage 2 明确的预算；
6. test 未参与选择。
